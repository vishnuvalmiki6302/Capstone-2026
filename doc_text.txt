SMA.AI Social Media Analytics & Intelligence Platform Complete MVP Specification for Final-Year Project Team Planning + Implementation Guide 1. MVP in One Sentence SMA.AI is an AI-powered web application that accepts publicly available social-media data through supported data sources or CSV/JSON upload, processes the text, performs sentiment and topic analysis, calculates engagement and time-based trends, and presents the results through an interactive analytics dashboard. 2. What the MVP Must Demonstrate The MVP should prove the complete end-to-end pipeline: User Login    ↓ Create Analysis / Upload Dataset    ↓ Validate + Store Social Posts    ↓ Preprocess Text    ↓ AI Analysis    ├── Sentiment    ├── Keywords / Topics    └── Engagement    ↓ Trend / Time-Series Aggregation    ↓ Dashboard    ├── KPI cards    ├── Sentiment chart    ├── Topic chart    ├── Trend chart    └── Post explorer    ↓ Generate Summary / Report 3. MVP Scope Feature MVP Decision Details Authentication YES Register/login using JWT; hashed passwords. Data input YES CSV/JSON upload; design an adapter layer for future APIs. Data preprocessing YES Cleaning, normalization, language handling, duplicate removal. Sentiment analysis YES Positive, negative, neutral + confidence/score. Topic/keyword analysis YES Top keywords and topic groups using TF-IDF + clustering/topic method. Engagement analysis YES Likes, comments, shares and a documented engagement score. Time-series trends YES Daily/hourly volume and sentiment trend. Post explorer YES Search/filter posts by date, sentiment, topic and source. Network graph MVP+ / optional Implement if interaction data contains relationships; otherwise use prepared demo dataset. Audience intelligence MVP+ Only aggregate, non-identifying insights. AI-generated summary MVP+ Generate a concise summary from calculated metrics; never invent statistics. Real-time streaming NO Future scope; not required for first MVP. Multiple live social APIs NO Future scope; API availability and policies can change. 4. Problem Statement Social-media platforms produce large amounts of text and interaction data. Manually understanding this information is slow and difficult. Existing analytics may show isolated metrics, but a student project can demonstrate greater value by combining text processing, sentiment analysis, topic discovery, engagement analysis and temporal trends in one interface. SMA.AI addresses this by converting available social-media data into structured analytical insights. 5. Objectives Collect or import publicly available social-media data through permitted sources. Clean and preprocess noisy social-media text. Classify posts into positive, neutral and negative sentiment. Identify important keywords and discussion topics. Measure engagement and compare posts/topics. Analyze how post volume and sentiment change over time. Provide searchable and filterable analytics through a web dashboard. Provide aggregate audience insights without exposing unnecessary personal information. Create downloadable analytical reports. Keep the architecture modular so future social-media APIs can be added without redesigning the whole system. 6. Users and Use Cases Actor Main Actions Analyst/User Login, upload dataset, create analysis, filter data, view sentiment/topics/trends, inspect posts, generate report. Admin Manage users, monitor analysis jobs, remove invalid datasets, view system status. 7. MVP Functional Modules A. Authentication Registration and login. JWT access token. Password hashing using bcrypt/Argon2. Protected analytics routes. B. Dataset Management Upload CSV/JSON. Validate required columns. Store dataset metadata. Track processing status: UPLOADED → PROCESSING → COMPLETED/FAILED. C. Data Preprocessing Remove duplicate posts. Normalize whitespace/case where appropriate. Extract hashtags and mentions. Remove or normalize URLs. Handle emojis and punctuation carefully. Detect/record language where possible. D. Sentiment Analysis Predict positive/neutral/negative. Store confidence or class scores. Aggregate sentiment by date/topic. Display a confusion matrix and F1/precision/recall during model evaluation. E. Topic and Keyword Analysis Find top keywords using TF-IDF. Group related terms/posts using a simple clustering or topic-modeling method. Calculate topic frequency and growth. F. Engagement Analysis Calculate interaction totals. Rank high-engagement posts/topics. Use a transparent project-defined score when impressions are unavailable. G. Trend Analysis Aggregate posts by day/hour. Plot volume over time. Plot sentiment over time. Flag unusually large changes as possible emerging activity. H. Dashboard KPI cards. Sentiment distribution. Sentiment-over-time chart. Top topics/keywords. Engagement ranking. Recent/analyzed posts table. Filters. I. Reporting Generate a PDF/CSV report from calculated results. Include dataset period, post count, sentiment distribution, top topics and trends. 8. Engagement Score When impression data is unavailable, the MVP can use a transparent internal score rather than calling it a universal engagement rate. Engagement Score = Likes + (2 × Comments) + (3 × Shares) The weights are a project-defined ranking rule and should be documented in the report. If a source provides a valid impressions/reach metric, a conventional engagement-rate formula can be used instead. 18. Trend Calculation Growth % = ((Current Period Mentions - Previous Period Mentions) / Previous Period Mentions) × 100 Use this to rank fast-growing topics. Add safeguards for a previous-period value of zero and avoid presenting growth from very small sample sizes as a major trend without context. 19. Privacy and Responsible Data Use Use only data that the project is authorized to access or datasets provided for research/demo use. Do not scrape or bypass platform access controls. Do not collect private messages or unnecessary personal information. Hash/anonymize author identifiers where possible. Show aggregate audience insights instead of personal profiling. Provide dataset/source information in the project documentation. Allow deletion of uploaded datasets from the application. Clearly label model predictions as predictions, not facts. 20. Start analysis and show processing status. Open the dashboard and show total posts, positive/neutral/negative percentages and engagement. Open sentiment trends and show how sentiment changed over time. Open topics and explain the most discussed subjects. Filter posts to show negative posts about a particular topic. Open engagement ranking to identify highly interactive posts. Generate the final report. If implemented, show the network graph and explain influential nodes/communities. 23. Example Team Explanation “SMA.AI is an AI-driven social-media analytics platform. The user first logs in and uploads or selects an authorized public dataset. The backend validates and stores the posts. Our NLP pipeline cleans the text and uses a sentiment model to classify each post as positive, neutral or negative. We then extract important keywords and topics and combine those results with engagement and timestamp information. The analytics layer calculates sentiment trends, topic growth and engagement rankings. Finally, our React dashboard presents the results as interactive charts and searchable post data. The MVP focuses on the complete end-to-end workflow rather than depending on multiple live social-media APIs. Network analysis, audience intelligence and AI-generated summaries are extensions that can be added after the core pipeline is stable.” 24. What NOT to Build in the First Version Do not build five different live social-media integrations before the core analytics works. Do not train a large language model from scratch. Do not build a complex microservice architecture for a college MVP. Do not collect unnecessary personal data. Do not promise real-time analytics if your system is batch-based. Do not claim prediction accuracy without testing the model. Do not add a feature simply because it looks impressive if the core data pipeline is unreliable. 25. MVP Success Criteria A user can register and log in. A user can upload a valid dataset. The system can process at least a few thousand records reliably on the demo machine. Each analyzed post receives a sentiment result. Top keywords/topics are produced. Sentiment and volume can be plotted over time. Engagement ranking is calculated from available fields. Dashboard filters work. Results are persisted in the database. A report can be generated. The complete flow can be demonstrated from login to final insight without manual database changes. 26.
